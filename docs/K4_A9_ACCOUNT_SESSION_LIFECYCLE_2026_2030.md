# K4-A9 | Akun, hak akses dan siklus sesi DEMO 2026–2030
**24 November 2026 | KODE DITULIS, BELUM DIUJI | CODE_ONLY.** Tidak membuat autentikasi nyata, login website, password, email, data personal, atau route HTTP. Tidak menjalankan Python/SQL/test.
- [Validator](../drafts/yandik-backend-contract/account_payload.py), [DDL](../drafts/yandik-backend-contract/account_payload.sql), [store](../drafts/yandik-backend-contract/account_store.py), [24 QA](../drafts/yandik-backend-contract/test_account_store.py) (6 pure + 18 rehearsal, 0 dijalankan). Lima tabel pendamping account head, access event, receipt, session, session event. AccountStore mewarisi ProjectionStore dalam SQLite :memory: dan menambah fixture admin/pimpinan. Akun berbeda dari master SDM.
- Session issuance hanya host in-process berdasarkan callback identitas fixture yang dianggap tepercaya; callback bukan autentikasi. Tidak boleh meneruskan body/query/header pengguna sebagai callback. Handle acak 32 byte dari secrets dibuat runtime, hanya SHA-256 digest disimpan; bukan hashing password. Handle mentah dikembalikan hanya ke host, tidak disimpan di repo, receipt, log atau respons API. Fixed TTL DEMO 1800 detik dari clock host; tidak sliding, tidak refresh token. Resolver instance-bound, lookup sesi + grant + actor aktif di dalam transaksi tiap request, termasuk replay. Logout idempotent, pencabutan grant/disable actor menutup sesi atomik. Tidak ada cookie/browser storage atau mekanisme pemulihan akun.
- Existing DraftAPI menerima exact AccountStore; AccountStore menolak callback mentah pada semua operasi turunan, menerima resolver dari handle valid. ProjectionStore lama tetap fixture-only untuk regresi, tidak boleh digunakan sebagai pintu autentikasi produksi. Default write API tetap off. 28 route kandidat tidak bertambah; administrasi akses hanya fungsi host, tanpa endpoint browser.
- Admin provinsi fixture dapat register actor, grant, revoke_grant, disable, enable dengan revision dan alasan enum. Dilarang mengubah diri atau actor dengan histori grant admin, membuat grant admin, punya lebih dari satu grant aktif, reaktivasi grant lama. Scope Puskeswan diturunkan dari master fasilitas, kab/kota wilayah valid, pimpinan/verifikator province. Enable actor tidak mengaktifkan grant lama; beri grant baru jika perlu. Grant baru tidak mengalihkan kepemilikan record lama; proses owner reassignment dan pergantian petugas resmi belum dibuat. Tidak ada admin delegation atau approval dua pihak; perlu keputusan SOP.
- Histori append-only per actor, before/after, administrator, waktu dan alasan; idempotency namespace akses DEMO-ACCESS-CMD terpisah dari DEMO-COMMAND; revocation dan access event/receipt atomik. Admin-only history maksimal 100 event terbaru tanpa token/hash. Trigger bukan anti-tamper. Session audit issuance/logout/revoke, belum log semua akses sensitif.
- Role dan kewenangan kandidat, bukan keputusan instansi. Belum auth/SSO/password KDF, reset/MFA, secure cookies/TLS/CSRF, brute-force protection, concurrent process, durable storage, backup/retention, owner transfer, atau audit keamanan. Jangan bind HTTP. Perlu izin QA unit/DDL dan sumber Flask terotorisasi.
- **A1–A9 kode awal tersedia; K4 dan K7 belum selesai/teruji.** Berikutnya K4-B konsolidasi statis kontrak dan penutupan gap lintas writer/API, siapkan handoff QA tanpa eksekusi selama CODE_ONLY; jangan mengulang prototype terpisah atau mengklaim siap produksi.
